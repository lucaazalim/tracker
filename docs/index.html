    How it works

    Locations are captured using the settings of the active profile, stored in a local SQLite queue, and uploaded in batches. A record is deleted only after the server acknowledges it.

    1. Capture

      Standard updates, significant-change updates and visits, as set in the active profile.

    2. Filter

      Points too close in distance or time to the previous one are dropped. Wi-Fi zones can replace or skip points.

    3. Queue

      Each record is serialized once and stored in SQLite on the device.

    4. Upload

      Batches are sent on the configured interval, on request, or during background app refresh.

    5. Acknowledge

      Records stay queued until the server confirms them, and failed batches are retried.

    Features

    The app is mostly settings. There's no map or history view: the data is meant to be used on your server.

    Profiles

    A profile is a named set of capture, upload and payload settings, for example Balanced or Battery saver. You can switch profiles in the app, with Shortcuts, or from the server's response.

    • UpdatesStandard, significant changes, or both
    • AccuracyBest for navigation to 3 km
    • PausingAutomatic, with a resume geofence
    • VisitsArrivals and departures

    Server

    Records are sent as GeoJSON batches or as OwnTracks objects. Authentication can be a bearer token, Basic auth or custom headers. The endpoint URL can include placeholders for receivers that take query parameters.

    • FormatsGeoJSON, OwnTracks
    • AuthBearer, Basic, custom headers
    • Placeholders%LAT %LON %ACC %TS
    • Success when"result": "ok" or any 2xx

    Request log

    The app keeps the last 200 requests with their headers, bodies and responses, with credentials masked. Test Connection sends an empty batch, so you can check a receiver without sending any data.

    • HistoryLast 200 requests
    • ShowsStatus, duration, size, full body
    • CredentialsMasked
    • ExportShare sheet

    Also included

    Offline queue

    Records are kept in SQLite until they're acknowledged. Limits on count and age stop an unreachable server from filling the device.

    Per-field payloads

    Each property can be turned on or off. Every toggle shows the JSON key it controls, and a preview shows the resulting record.

    Wi-Fi zones

    While connected to a listed network, record a fixed coordinate instead of GPS, or record nothing.

    Health checks

    Shows permission, precise location, Background App Refresh and receiver status. An optional notification fires if no location arrives for a while.

    Shortcuts and Siri

    Actions to start and stop tracking, switch profile, upload queued records, and get the queue size.

    Links and QR codes

    Export a configuration as JSON, a tracker:// link or a QR code. Imports are shown for review before they apply.

    Compatible receivers

    Any receiver that accepts Overland-style GeoJSON batches, or OwnTracks over HTTP, should work. You can enter the endpoint by hand or open a setup link.

    Privacy

    Tracker sends data only to the endpoint you configure. Queued records and settings stay in the app's sandbox until they're uploaded or deleted.

    No account

    There's nothing to sign up for, and no intermediate service.

    No analytics

    No telemetry, crash reporting or third-party dependencies.
